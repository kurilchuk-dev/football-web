# Правила проєкту

## Гілки

Формат назви: `<type>/<короткий-опис-kebab-case>`

| Тип        | Для чого                         |
| ---------- | -------------------------------- |
| `feat`     | нова функціональність            |
| `fix`      | виправлення помилки              |
| `hotfix`   | термінове виправлення            |
| `refactor` | зміна коду без зміни поведінки   |
| `perf`     | покращення продуктивності        |
| `docs`     | лише документація                |
| `style`    | форматування, без зміни логіки   |
| `test`     | додавання чи виправлення тестів  |
| `chore`    | інструменти, залежності, конфіги |
| `ci`       | налаштування CI                  |
| `build`    | збірка проєкту                   |

Приклади: `feat/match-list`, `fix/header-overflow`, `chore/update-deps`.

- Лише малі літери, цифри та дефіси. Без підкреслень, великих літер і пробілів.
- Бажано 2–5 слів.
- Одна задача — одна гілка.
- Створювати від актуальної `develop` (hotfix — від `main`).
- Після мерджу гілку видаляти.
- `main` і `develop` дозволені як є.

## Робочий процес (develop / main)

- `main` — лише продакшн. Оновлюється тільки під час релізів (`develop` → `main`). Прямих комітів немає.
- `develop` — основна гілка розробки. Усі робочі гілки створюються від неї й мерджаться назад у неї.
- Реліз: PR `develop` → `main` (звичайний merge, без squash), потім тег версії.
- Hotfix: гілка `hotfix/...` від `main`, PR у `main`, після цього `main` мерджиться назад у `develop`.

## Коміти

Формат [Conventional Commits](https://www.conventionalcommits.org): `type(scope): опис`

- Опис в наказовому способі, з малої літери, без крапки в кінці.
- Приклад: `feat(matches): add live score badge`.
- Типи ті самі, що й для гілок.

## Pull request

- Заголовок у форматі коміту.
- PR невеликий і сфокусований.
- Перед PR має проходити `npm run check`.
- Цільова гілка PR — `develop` (не `main`), мердж через squash.

## Автоматичні перевірки (Husky)

| Хук          | Що робить                                                   |
| ------------ | ----------------------------------------------------------- |
| `pre-commit` | назва гілки, потім lint-staged (`oxlint --fix`, `prettier`) |
| `commit-msg` | commitlint перевіряє повідомлення коміту                    |
| `pre-push`   | назва гілки, потім typecheck і lint                         |

Якщо перевірка не пройшла, коміт або пуш буде заблоковано.
Перейменувати гілку: `git branch -m <нова-назва>`.

## Форматування

- Prettier: одинарні лапки, крапки з комою, `trailingComma: all`, ширина рядка 100.
- EditorConfig: LF, відступ 2 пробіли, UTF-8.

## Скрипти

| Команда                | Призначення                                     |
| ---------------------- | ----------------------------------------------- |
| `npm run dev`          | запуск dev-сервера                              |
| `npm run build`        | збірка                                          |
| `npm run typecheck`    | перевірка типів                                 |
| `npm run lint`         | oxlint                                          |
| `npm run format`       | форматування Prettier                           |
| `npm run format:check` | перевірка форматування                          |
| `npm run check`        | typecheck + lint + перевірка форматування разом |
